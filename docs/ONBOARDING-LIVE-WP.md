# AgentBadge — установка на живой WP (pryme.studio)

Инструкция для установки плагина на живой сайт и подключения к
AgentBadge Cloud. Выполняется в браузере — код писать не нужно.

**Что понадобится (выдаёт координатор):**
1. Файл `agentbadge-X.Y.Z.zip` — архив плагина
2. Site key вида `absk_...` — одна строка, выдаётся один раз
3. Логин/пароль в админку https://pryme.studio/wp-admin/

Если чего-то из списка нет — пишите координатору, дальше идти
нельзя (ключ нельзя «установить позже», он вводится на шаге 5).

---

## Шаг 1 — Войти в админку WordPress

Открыть https://pryme.studio/wp-admin/ → ввести логин и пароль →
должна открыться консоль (Dashboard) с тёмным меню слева.

## Шаг 2 — Загрузить плагин

- Левое меню → **Плагины** → **Добавить новый** (вверху страницы
  кнопка «Add New Plugin», рядом кнопка **«Upload Plugin»**)
- Нажать **«Выберите файл»** → выбрать `agentbadge-X.Y.Z.zip`
- Нажать **«Установить сейчас»** → дождаться «Plugin installed
  successfully»
- Нажать **«Активировать плагин»** (Activate Plugin)

Если кнопки «Upload Plugin» нет — на этом хостинге отключена
загрузка. Пишите координатору — плагин зальём по FTP.

## Шаг 3 — Проверить, что плагин встал

- Левое меню → **Плагины** → в списке должен быть
  **AgentBadge — Agent Readiness**, статус «Активен»
- В левом меню должен появиться пункт **AgentBadge**

## Шаг 4 — Открыть настройки плагина

- Левое меню → **AgentBadge** → откроется страница с двумя
  вкладками: **Scan** и **Cloud**
- Перейти на вкладку **Cloud**

## Шаг 5 — Подключить site key

- В поле для ключа вставить строку `absk_...` целиком
  (без пробелов и кавычек)
- Нажать **Connect**
- Должен появиться статус **«Connected — baseline self-report
  sent»** и таблица с `site_id` (вида `site_...`)

**Если вместо «Connected» ошибка:**
- `bad_key` — ключ скопирован не полностью/с пробелами → ввести заново
- `handshake_failed` — ключ отозван или Cloud недоступен →
  скриншот координатору, самому не перебирать варианты

## Шаг 6 — Прогнать локальное сканирование

- Вкладка **Scan** → нажать кнопку сканирования → дождаться
  результата (таблица проверок с статусами pass/warn/unknown)

## Шаг 7 — Отчитаться

Написать координатору:
- `site_id` из вкладки Cloud (вида `site_...`)
- «Connected — да/нет»
- «Скан прогнался — да/нет»
- Скриншот страницы AgentBadge, если что-то выглядит не так

После этого координатор включает диагностические pull-jobs —
с вашей стороны больше ничего не требуется.

---

## Что делает координатор (не для джуниора)

- Собрать zip: `make zip` → `dist/agentbadge.zip` +
  `dist/agentbadge.zip.sha256` (beta-канал SLICE-262-24 — то же
  дерево, что пойдёт на wp.org; отличается только
  `AGENTBADGE_API_BASE` в wp-config.php целевого сайта)
- Создать сайт на intel-сервере: tenant → customer → site
  (domain pryme.studio) → issue `absk_` (показывается один раз)
- Выдать trial-план (`assignPlan`) + проверить, что handshake
  сам грантит `audit` consent
- После отчёта джуниора: создать pull-job `ownership_verify` /
  `diagnostics` и принять результат (SLICE-262-17)
- **Важно:** если сайт ранее был подключён к ДРУГОМУ бэкенду
  (staging/dev), перед Connect обязателен один Disconnect —
  он сбрасывает TOFU root-pin (баг, найденный на pryme.studio
  при переходе ngrok→prod, фикс в reporter.php)
